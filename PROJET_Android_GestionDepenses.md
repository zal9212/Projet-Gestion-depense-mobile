Spécifications   Fonctionnelles  2.1 Module Gestion des   Dépenses  2.1.1 Saisie d'une   dépense  L'utilisateur doit pouvoir enregistrer une   dépense   avec les champs suivants :  •   Montant (obligatoire,   décimal )  •   Catégorie   (obligatoire, choix dans une liste)  •   Rubrique /   sous - catégorie   (optionnelle)  •   Date (obligatoire, par   défaut   : date du jour)  •   Description / note (optionnelle, texte libre)  •   Moyen de paiement :   Espèces , Mobile Money, Carte, Autre (optionnel)  2.1.2 Consultation et gestion  •   Afficher la liste de toutes les   dépenses   (tri par date,   décroissant )  •   Modifier une   dépense   existante  •   Supprimer une   dépense   (avec confirmation)  •   Filtrer la liste par   période   (jour, semaine, mois en cours)  •   Filtrer par   catégorie  2.2 Module Gestion des Revenus  2.2.1 Saisie d'un revenu  •   Montant (obligatoire,   décimal )  •   Source : Salaire, Commerce, Freelance, Don, Autre  •   Date (obligatoire, par   défaut   : date du jour)  •   Description (optionnelle)  2.2.2 Calcul du solde disponible  •   Solde = Total Revenus   -   Total   Dépenses   sur la   période   sélectionnée  •   Affichage permanent du solde sur l' écran   principal  •   Indicateur visuel : solde positif (vert) ou   négatif   (rouge)  2.3 Module   Catégories   et Rubriques  2.3.1   Catégories   prédéfinies  L'application doit proposer les   catégories   suivantes par   défaut   :  Categorie   Exemples de rubriques  Alimentation   Restaurant, Marche,   Épicerie , Fast - food  Transport   Taxi, Bus, Carburant, Parking  Logement   Loyer,   Electricité , Eau, Internet  Sante   Pharmacie, Consultation,   Hôpital

Regles Metier  5.1 Calcul du solde  Solde du mois = Somme des revenus du mois   -   Somme des depenses du mois Le mois  de reference est le mois calendaire en cours (1er au dernier jour du mois).  5.2 Gestion des plafonds  •   Un plafond est defini par mois calendaire (non glissant)  •   Le pourcentage de consommation = (depenses categorie / plafond) x 100  •   Le reliquat = plafond   -   depenses de la periode  •   Si aucun plafond n'est defini pour une categorie, la rubrique s'affiche sans barre de  progression  •   Le budget global est independant des budgets par categorie  5.3 Validations obligatoires  •   Le montant doit etre strictement superieur a 0  •   La date ne peut pas etre dans le futur (pour les depenses et revenus)  •   Le plafond defini doit etre superieur a 0  •   Une categorie ne peut pas etre supprimee si des depenses lui sont associees  6 . Exigences d'Interface  6.1 Principes generaux  •   Language de l'interface : Francais  •   Design : Material Design (librairie com.google.android.material)  •   Devise par defaut : FCFA (XOF)   -   configurable dans les parametres  •   Format de date : JJ/MM/AAAA  •   Support du mode portrait uniquement (paysage non requis)  6 .2 Composants UI obligatoires  Composant   Utilisation  RecyclerView   Toutes les listes : depenses, revenus, categories, budgets  CardView   Chaque element de liste + cartes du dashboard  FloatingActionButton (FAB)   Ajout d'une depense ou d'un revenu  ProgressBar horizontale   Suivi des plafonds budgetaires  Spinner (Dropdown)   Selection categorie, rubrique, moyen de paiement  TextInputLayout (Material)   Tous les champs de saisie  BottomNavigationView   Navigation entre les 4 sections  Snackbar   Messages de confirmation (suppression, sauvegarde)  AlertDialog   Confirmation avant suppression
